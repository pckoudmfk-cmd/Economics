# Finance Quest App

Автономная версия командного квеста «GFP Advisory — Case Rotation». В отличие от версии, опубликованной как Claude Artifact, это обычный веб-проект без зависимости от среды Claude, который разворачивается на Vercel и хранит данные в Firebase.

## Что здесь есть

- `public/index.html` — вся страница: вход, шесть станций квеста, панель преподавателя. Один файл, без сборки.
- `api/teacher-login.js` — серверная функция Vercel, которая проверяет PIN преподавателя и выдаёт токен доступа.
- `firestore.rules` — правила доступа к базе данных, их нужно вставить в консоль Firebase.
- `.env.example` — список переменных окружения, которые нужно задать в Vercel.

## Как это устроено (коротко)

Каждый посетитель страницы сразу и незаметно для себя входит в Firebase анонимно — это нужно, чтобы база данных вообще пускала браузер на чтение и запись. Когда преподаватель вводит PIN, браузер отправляет его на серверную функцию `api/teacher-login.js`, та сверяет PIN с переменной окружения `TEACHER_PIN` и, если он верный, выдаёт токен с меткой «преподаватель». Именно эта метка, а не сам PIN, дальше проверяется в правилах Firestore, поэтому PIN нигде не хранится в коде страницы.

Код команды, который преподаватель создаёт на панели, играет роль общего пароля для группы: любой, кто его знает, может присоединиться и редактировать общий документ команды. Такая модель доверия совпадает с обычной аудиторной практикой (код написан на доске), но не защищает от человека, который узнал чужой код намеренно.

## Пошаговая настройка

### 1. Создать проект Firebase

1. Откройте [console.firebase.google.com](https://console.firebase.google.com) и создайте новый проект (бесплатного тарифа Spark достаточно).
2. В разделе **Build → Firestore Database** нажмите «Create database», выберите режим **Native mode** и любой регион.
3. В разделе **Build → Authentication → Sign-in method** включите провайдера **Anonymous**.
4. В разделе **Project settings → General → Your apps** нажмите «Add app» → веб-приложение (значок `</>`), дайте ему любое имя. Firebase покажет объект `firebaseConfig` с полями `apiKey`, `authDomain`, `projectId` и так далее.
5. Откройте `public/index.html`, найдите в начале `<script type="module">` объект `firebaseConfig` и замените в нём значения `PASTE_YOUR_...` на те, что показал Firebase. Эти значения не секретны, их можно смело хранить в открытом файле — доступ регулируют правила Firestore, а не секретность этих полей.

### 2. Вставить правила доступа

1. В консоли Firebase откройте **Firestore Database → Rules**.
2. Скопируйте содержимое файла `firestore.rules` из этого проекта и вставьте вместо того, что там есть по умолчанию.
3. Нажмите «Publish».

### 3. Получить служебный ключ (service account)

1. В консоли Firebase откройте **Project settings → Service accounts**.
2. Нажмите «Generate new private key», подтвердите — скачается файл `xxxxx.json`. Храните его отдельно от репозитория, в git его добавлять не нужно.
3. Закодируйте файл в base64 одной строкой:
   ```
   base64 -i service-account.json | tr -d '\n'
   ```
   (на Windows: `certutil -encode service-account.json tmp.b64`, затем убрать первую и последнюю строки файла).
4. Результат понадобится на следующем шаге.

### 4. Развернуть на Vercel

1. На [vercel.com](https://vercel.com) нажмите «Add New… → Project» и выберите репозиторий `economics`.
2. При импорте укажите **Root Directory**: `finance-quest-app` (это важно — иначе Vercel попытается собрать весь репозиторий целиком).
3. Framework Preset можно оставить «Other» — сборка не нужна, `vercel.json` уже указывает, что статические файлы лежат в `public/`.
4. В разделе **Environment Variables** добавьте:
   - `TEACHER_PIN` — придумайте свой PIN для входа преподавателя;
   - `FIREBASE_SERVICE_ACCOUNT_BASE64` — вставьте строку, полученную на шаге 3.
5. Нажмите «Deploy». После первого деплоя Vercel даст ссылку вида `https://finance-quest-app-xxxx.vercel.app` — это и есть рабочий адрес приложения.

Дальше при каждом пуше в подключённую ветку репозитория Vercel будет пересобирать и обновлять сайт автоматически.

### 5. Проверить

1. Откройте развёрнутую ссылку, выберите «Teacher», введите PIN — должна открыться пустая панель преподавателя.
2. Нажмите «+ Create new team code», получите код.
3. Откройте ссылку в другой вкладке (или дайте другому человеку), выберите «Student team», введите этот код и любое имя.
4. Впишите что-нибудь в любое поле на первой станции — в панели преподавателя, если её обновить, должен появиться прогресс этой команды.

## Известные ограничения

- PIN преподавателя один общий на всех преподавателей, использующих это развёртывание. Если нужно несколько отдельных PIN — на будущее.
- Правила Firestore разрешают писать в любую существующую команду любому вошедшему пользователю. Это соответствует модели «код на доске = общий пароль команды», а не индивидуальной аутентификации каждого студента.
- Бесплатный тариф Firebase Spark ограничивает количество операций чтения/записи в сутки; для одной группы или потока это с большим запасом хватает, но при очень активном использовании стоит свериться с лимитами в консоли Firebase.
